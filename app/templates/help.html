Adding a single event

Click + Add event. Title and first day are the only required fields — you can save with just those and come back later for judges, fees, and links. The days of the week are worked out from the dates automatically; never type them. {% if user.role == 'governor' %}Events you add always belong to your region ({{ user.region }}), whatever else is on the form.{% endif %}

Editing an event

Click Edit on any row. {% if user.role == 'governor' %}You can edit events in your own region only.{% else %}Admins can edit any event, in any region or none.{% endif %} Change the dates and the calendar, grid, and printable page all update themselves.

Cancel vs Hide{% if user.role == 'admin' %} vs Remove{% endif %}

  • Cancel — the trial is off, and you want everyone to know. It stays on the public calendar, struck through and marked CANCELED. Use this when a trial was announced and then called off. Reinstate undoes it.
  • Hide — take it off the public site without changing anything. The event stays right where it is on your dashboard with a gray hidden tag, and Unhide puts it back. Use this for events that shouldn't be shown (old trials, placeholders, not-yet-confirmed dates).
    • {% if user.role == 'admin' %}
  • Remove (admins only) — for events that shouldn't be on anyone's list at all, e.g. a duplicate created by mistake. It moves to the "Removed events" section at the bottom of the dashboard, where Restore brings it back. Even Remove is not a true delete — the event and its whole history are kept.
    • {% endif %}

Excel: add a schedule, edit events, or draft next year

The Spreadsheet (Excel) card on the dashboard covers three jobs:

  • Add new trials — download the blank template (the familiar interclub schedule format), fill one row per trial, upload. Rows already on the calendar are skipped, so uploading twice is harmless.
  • Edit existing trials — download the calendar's current events for a year. That file carries an EVENT ID column; change dates, clubs, cities, or stakes in Excel, re-upload, and those same events are updated. You're shown every change for confirmation before anything is saved, and the whole upload has an Undo afterward.
  • Draft next year from this year — download this year, change the dates to next year, tick "treat every row as new" when uploading. (Or skip Excel entirely and use Roll a season forward.)

Judges, fees, and links aren't in the spreadsheet — edit those on the event page.

Ticking several events at once

Every table on the dashboard has checkboxes (the box in the header row ticks a whole section). Tick some events, pick an action in the bar above the tables — Hide, Unhide, Cancel, Reinstate{% if user.role == 'admin' %}, Remove, Restore{% endif %}, or Shift dates by N days — and click Apply. Shifting by 7 moves everything one week later and keeps the days of the week; −7 moves a week earlier. Useful when a whole circuit moves a weekend. Ticked-event runs are batches too, so they can be undone.

Each row also has a Copy → next year button: one click copies that trial to the same weekend next year (same rules as the roll-forward) and opens it for adjusting.

Bulk hide / unhide

Bulk hide / unhide on the dashboard changes many events in one step — for example, hiding every trial from January 1st up to today. Pick the action and the date range{% if user.role == 'admin' %} and region{% endif %}, and click Preview. You always get the full list of matching events, with a count, before anything happens; nothing changes until you confirm. {% if user.role == 'governor' %}It only ever touches {{ user.region }} events.{% endif %}

Roll a season forward

Trials mostly run on the same weekend every year. Roll a season forward copies a year's trials into the next year in one step: each event lands on the same weekend and the same days of the week (a Saturday–Sunday trial stays Saturday–Sunday). Club, city, state, grounds, and stakes carry over. Judges, fees, closing dates, links, and notes do not — they change every year, so the new events start blank.

The preview shows every proposed event with its new dates. Untick any you don't want. Trials already entered for the new year are skipped automatically, and canceled trials are not copied. After creating, open each event to adjust its exact date or add judges as they're confirmed.

Undoing a bulk mistake

Every bulk run — a bulk hide or unhide, a ticked-events action, a date shift, a spreadsheet edit upload, a roll-forward, a copy-to-next-year — is saved as a batch. The page that ran it shows an Undo button immediately afterward, and the Bulk hide / unhide page lists recent batches with their Undo buttons, so you can also undo later. Undo puts every event the batch touched back exactly as it was.

What the public actually sees

The public list, calendar, and grid show upcoming events only — past events drop off by themselves the day after they end (they're still there via the "include past events" link, and on your dashboard under "Past events"). Canceled events stay visible, struck through. Hidden and removed events never appear. The printable page shows the whole chosen year. The iCal feed carries scheduled events only.

Administrator tools

  • Manage governors (/users) — add a governor (the password is generated and shown exactly once — copy it before leaving the page), reset a password, deactivate an account (they can no longer sign in; their events and history remain). The "Last signed in" column answers "has this governor actually been in?"
  • Audit log (/audit) — every sign-in, failed attempt (shaded red), and sign-out, filterable by account and date, plus a feed of recent event changes with who made them. Failed attempts from an unfamiliar IP in a cluster mean someone is guessing passwords — the built-in rate limit slows them down, but tell Albert.
  • Region on the bulk pages — admins can point bulk actions and roll-forward at any region, or at the no-region events (Hunt Tests, Nationals, seminars).
